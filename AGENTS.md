# AGENTS.md

## Project overview

ESP8266 embedded firmware (ESP8266 RTOS SDK / ESP-IDF) that drives an SSD1306 OLED display over I2C to log indoor environment data. C++ with C interop.

## Build systems

Two build systems exist — know which one you're using:

- **Makefile** (legacy ESP8266 RTOS SDK): requires `export RTOS_SDK=~/ESP8266_RTOS_SDK`, then `make`
- **CMakeLists.txt** (ESP-IDF): requires `export IDF_PATH=<path>`, then `idf.py build`

The CMake/IDF path is the primary one. The Makefile is leftover from an earlier SDK setup.

## Entry point

`app_main()` in `main/main.cpp` — **not** `user_init` (README is outdated on this point).

All FreeRTOS and ESP SDK headers must be wrapped in `extern "C" {}` when included from C++ files.

## Architecture

- `main/main.cpp` — app entry, currently uses the C SSD1306 API directly; the C++ `OLEDDriver` wrapper exists but is commented out
- `main/ssd1306.c` + `main/include/ssd1306.h` — C SSD1306 driver (third-party, MIT licensed)
- `main/OLEDDriver.cpp` + `main/include/OLEDDriver.hpp` — C++ wrapper around the C driver (incomplete/unused)
- `main/fonts/` — compile-time font library; font selection via flags in `main/fonts/defaults.mk`; font data generated by `main/fonts/tools/create_font.py`
- `main/CMakeLists.txt` — registers `main.cpp`, `ssd1306.c`, and `fonts/fonts.c` as component sources

## Hardware config

- Target: ESP8266, xtensa-lx106-elf toolchain, 2MB flash
- I2C bus 0: SDA=GPIO4, SCL=GPIO5 (NodeMCU pins D2/D1)
- Flash mode QIO, 40 MHz; serial monitor baud 74880
